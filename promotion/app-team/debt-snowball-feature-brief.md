# Debt Snowball Calculator — 기능 브리핑

코드베이스(`debtsnowballmobileready.zip`)를 직접 읽고 정리한 문서입니다. `app-review-responder`, `app-comment-manager`는 답변 작성 전 이 문서를 먼저 참고하세요. 마케팅 문구가 아니라 "실제로 코드에 구현된 것"만 기록했습니다.

## 제품 개요

- 앱 내 표기 이름: **Debt Snowball Calculator** (부제: "Debt Snowball Payoff Simulator")
- 구조: pnpm 모노레포. 프론트엔드(`artifacts/debt-calculator`, Vite+React+TS, Tailwind/shadcn UI), 백엔드(`artifacts/api-server`, Express 5), DB(PostgreSQL + Drizzle ORM)
- **중요**: 코드상 Capacitor/React Native/Expo 등 네이티브 래퍼가 전혀 없습니다. 즉 현재는 **반응형 웹앱**이며, "mobile ready"는 모바일 브라우저에서 잘 보이는 반응형 UI를 의미하는 것으로 보입니다. 앱스토어/플레이스토어에 실제로 등록되어 있는지는 코드로 확인 불가 — 리뷰/평점 관리 채널을 앱스토어 기준으로 잡을지, 웹 기준(예: Product Hunt, 자체 사이트 후기)으로 잡을지 먼저 확인이 필요합니다.

## 핵심 기능 (실제 구현 확인)

### 1. 부채 입력
- 항목: 이름, 잔액, 연이율(%), 최소 상환액, 대출 기간(개월, 선택), 결제일(1~31일, 선택)
- 잔액·이율·대출기간을 입력하면 표준 상환 공식으로 **최소 상환액을 자동 계산**해줌 (수동 수정도 가능)
- 최대 15개 부채까지 등록 가능

### 2. 상환 전략 시뮬레이션 (`lib/calculator.ts`)
- **Baseline**: 최소 상환액만 냈을 때의 예상 상환 기간·총 이자
- **Snowball**: 여윳돈(추가 상환액)을 잔액이 가장 적은 빚부터 몰아줌
- **Avalanche**: 여윳돈을 이율이 가장 높은 빚부터 몰아줌
- **Hybrid**(사용자가 말한 "스노우볼+아발란치 하이브리드"): 이율 정규화 점수와 잔액 정규화 점수를 5:5로 섞어 우선순위를 정하는 실제 하이브리드 알고리즘 — 단순 평균이 아니라 자체 스코어링 로직으로 구현되어 있음
- 빚 하나를 다 갚으면 그 최소상환액이 자동으로 다음 빚에 대한 여윳돈에 합산됨 (진짜 "눈덩이" 효과)
- 추가 상환 방식 4종: 매달 고정 / 1회성 / 지정 개월수만 / 지정 연수만

### 3. 자동 잔액 업데이트
- 앱을 다시 열면, 등록된 결제일 기준으로 지난 결제 횟수를 계산해 잔액을 자동으로 갱신 (localStorage에 마지막 체크 시각 저장) — 매달 수동으로 잔액을 다시 입력할 필요 없음

### 4. 결과 시각화
- Interest Saved / Time Saved 큰 숫자 카드 (Baseline 대비 Hybrid)
- 상환 순서 타임라인 (어떤 빚이 몇 개월 차에 끝나는지)
- 잔액 변화 라인 차트 (Baseline vs Hybrid 비교)
- 월별 이자/원금 스택 바 차트 + 상세 테이블 (Baseline / Hybrid / Per-Debt 탭 전환), "완납" 행 하이라이트
- 리포트: 브라우저 인쇄창을 여는 방식 — **파일로 바로 다운로드되는 PDF가 아니라 "인쇄 → PDF로 저장"** 방식임. "1클릭 PDF 다운로드"처럼 홍보하지 않기

### 5. 다중 통화
- USD/EUR/GBP/JPY/KRW/CNY/AUD/CAD/MXN/BRL/INR/SGD 12개 통화 선택 가능 (국기 아이콘 포함)

### 6. 계정 & 무료/프리미엄 구분
- 이메일/비밀번호 회원가입·로그인 (세션 토큰, 7일 만료)
- **무료(비로그인)**: 부채별 입력 + 부채별 예상 이자 breakdown까지는 보임 ("Free Preview")
- **로그인 후 잠금 해제되는 것**: Hybrid 최적화 결과 요약, 월별 상세 breakdown, 리포트 생성, 시나리오 저장/불러오기
- 로그인한 사용자는 이름 붙여서 시나리오(부채 구성+추가상환 설정+통화)를 저장하고 나중에 불러올 수 있음
- 관리자 계정은 별도 어드민 화면에서 사용자 승인/거절, 전역 페이월 on/off, 데모 모드 on/off를 제어

**주의(코드 불일치 발견)**: 회원가입 화면에는 "가입 후 관리자 검토를 거쳐 활성화됩니다"라는 안내 문구가 있지만, 실제 백엔드 코드(`routes/auth.ts`)는 가입 즉시 `status: "approved"`로 처리해 바로 프리미엄 잠금이 풀립니다. 관리자 승인이 실제 운영 방식인지, 즉시 승인이 의도된 동작인지 사용자 확인이 필요합니다 — 확인 전까지는 "가입 시 관리자 승인이 필요합니다" 같은 문구로 홍보/응대하지 않는 것을 권장합니다.

## 알려진 제약 (과장 홍보 방지용)

- 부채는 최대 15개까지만 등록 가능
- 시뮬레이션은 최대 600개월(50년)까지만 계산 (사실상 실사용에 문제 없는 수준)
- "PDF 리포트"는 브라우저 인쇄 기능 기반 (위 참고)
- 네이티브 앱스토어 배포 여부 코드로 확인 불가 (위 참고)

## 리뷰/댓글 응대 시 활용 팁

- "정확히 어떻게 계산하나요?" → 스노우볼(최소잔액 우선)과 아발란치(최고이율 우선)를 5:5 가중치로 섞은 하이브리드 전략이라고 정확히 설명 가능
- "빚 다 갚으면 자동으로 반영되나요?" → 네, 완납된 빚의 최소상환액이 자동으로 다음 빚 여윳돈에 합산됩니다
- "PDF로 바로 저장되나요?" → 브라우저 인쇄 다이얼로그를 통해 PDF로 저장하는 방식이라고 정확히 안내 (과장 금지)
- "몇 개까지 등록 가능해요?" → 최대 15개
- "앱스토어에도 있나요?" → 코드 기준으로는 확인 불가. 실제 배포 채널을 사용자에게 먼저 확인할 것
